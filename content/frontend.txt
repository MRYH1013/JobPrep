# 前端开发
## JavaScript 工程师|js|从语言行为出发，手推执行过程，再解释边界与可测试性。
闭包为什么可能导致内存持续增长？|闭包保留对词法环境的访问，问题通常在长生命周期回调持续引用大对象。用堆快照定位引用链，移除监听与无效缓存，再验证对象能否回收。|闭包本身不是内存泄漏的充分条件。|如何复现并验证修复有效？
原型链查找属性的过程是什么？|先查对象自有属性，再沿原型逐层查找，直到空原型。区分实例、构造函数和 prototype；修改共享原型会影响多个实例。|不要把 prototype 与对象的内部原型混为一谈。|Object.create(null) 适合什么场景？
this 在箭头函数和普通函数中有何不同？|普通函数的 this 与调用方式有关，箭头函数从外层捕获 this。说明方法调用、显式绑定和回调脱离对象后的差别。|箭头函数不能通过 bind 改写其词法 this。|对象方法传给定时器后会怎样？
Promise.all 和 allSettled 如何选？|需要全部成功才继续时用 all；要收集每项成功或失败时用 allSettled。all 提前拒绝不会自动取消其他已经发出的操作。|聚合失败不等于底层请求已经终止。|如何限制并发请求为四个？
深拷贝为什么不适合直接用 JSON 转换？|JSON 序列化不保留全部 JavaScript 类型，也不能处理循环引用。先明确要复制的结构，再判断 structuredClone 或业务定制转换是否适合。|复制对象也不代表资源和类行为都能复制。|带函数和 DOM 节点的对象怎么办？
防抖和节流怎样处理最后一次调用？|防抖围绕静默窗口执行，节流限制单位时间频率。明确 leading、trailing、取消和返回值需求，再用假定时间线验证边界。|只展示定时器代码会漏掉取消和连续触发行为。|输入完成后需要立即提交怎么设计？
如何设计能取消的异步任务池？|维护待处理队列、活跃计数和取消信号，每完成一项再补位。取消时停止派发，并让支持信号的底层任务结束；收集部分结果与失败原因。|取消队列不代表正在运行的任务已经退出。|某项长期不结束如何避免占满容量？
## React 工程师|react|从状态与组件身份解释行为，用最小组件复现，再讨论工程取舍。
React 中 key 为什么不能随便使用数组下标？|key 参与同级元素身份识别，重排时下标可能把原来的状态绑定到另一条数据。优先用稳定业务标识，不要每次渲染随机生成。|key 不只是为了消除控制台警告。|输入列表删除中间一项会发生什么？
为什么连续调用 setState 不能直接当作立即赋值？|当前 render 读取的是状态快照；多个更新可能被批处理。依赖前一状态时使用函数式更新，避免基于旧快照重复计算。|不要只背异步更新，需说明闭包和更新队列。|一个事件中三次加一怎么写？
useEffect 的清理函数应该负责什么？|清理本次同步建立的订阅、计时器或外部连接，依赖变化前和卸载时释放旧资源。保持建立与清理对称，防止重复监听。|清理不是只在组件卸载时才有机会运行。|开发环境重复建立连接如何定位？
useMemo 和 useCallback 什么时候有价值？|在计算确实昂贵或引用稳定性有实际消费者时使用。先测量，再考虑依赖成本和代码复杂度；它们不能修复错误的状态模型。|缓存不是业务语义保证，也不能省略真实依赖。|子组件没有 memo 时引用缓存还有什么作用？
组件共享状态应该放在哪里？|先找到需要该状态的最低公共所有者，明确唯一事实来源；跨层传递可用 context，复杂外部状态再评估专用存储。|不要为了省几次传参把所有状态放全局。|高频更新的 context 如何拆分？
React 请求竞态如何避免？|区分每次请求的生命周期，清理时取消或忽略旧响应，只让当前查询写回数据。将 loading、错误与结果绑定到同一请求身份。|防抖只能减少请求，无法保证返回顺序。|同一个关键词重试如何区分请求？
如何让大表单更新更流畅？|定位更新范围与校验开销，按字段拆分状态和订阅；将非紧急结果渲染与输入反馈分离，并测量真实输入延迟。|不要为所有输入增加无依据的 memo。|远程校验与本地校验如何协作？
## Vue 工程师|vue|区分响应式追踪、派生计算和副作用，给出可观测的小案例。
Vue 的 reactive 和 ref 如何选择？|reactive 适合对象代理，ref 为值提供可追踪容器。注意解构、替换整个对象和模板解包规则，让状态更新路径保持明确。|解构 reactive 的普通属性可能失去原有追踪关系。|使用 toRefs 后有什么变化？
computed 和 watch 的职责有何差别？|computed 用于从响应式依赖得到派生值，watch 适合发生变化时执行外部副作用。不要用 watch 反复复制能直接计算出的状态。|computed getter 应尽量保持无副作用。|异步请求适合放在哪里？
watch 和 watchEffect 应该怎么选？|watch 明确指定来源并能取得新旧值，watchEffect 自动追踪同步执行时访问的依赖。来源复杂时优先考虑可理解性和清理机制。|await 之后新读取的依赖不能想当然地被自动追踪。|如何取消上一次异步监听任务？
为什么修改状态后立刻读 DOM 可能拿到旧值？|状态变化会触发批量更新，DOM 提交通常不是逐次同步执行。确需更新后的尺寸时等待 nextTick，再做有限的布局读取。|不要用固定 setTimeout 时长替代更新语义。|大量读写布局怎么避免抖动？
Vue 组件双向绑定应该怎样设计？|让值与更新事件构成清晰契约，父组件保留状态所有权；复杂组件区分展示值、编辑草稿和提交值，避免直接修改 props。|双向绑定不等于组件可以任意写入父状态。|取消编辑时如何恢复原值？
列表渲染的 key 与状态保留有什么关系？|稳定 key 帮助识别同一数据对应的节点与组件，重排时减少状态错配。业务 ID 优于依赖位置的标识。|随机 key 会让组件频繁重新创建。|可编辑列表重新排序后光标如何保持？
可复用组合式函数应该怎样管理副作用？|把输入依赖、返回状态和资源生命周期写清楚，在适当时机停止监听与订阅；避免隐式共享可变状态导致实例相互影响。|复用代码不代表应当共享所有状态。|同一个 composable 被调用两次如何测试隔离？
## TypeScript 工程师|ts|先定义输入输出契约，再说明类型系统能保证什么、运行时还需验证什么。
unknown 与 any 有什么不同？|unknown 要经过检查和收窄才能安全使用，any 会绕过大量检查。外部输入优先使用 unknown 并做结构验证。|类型断言不能替代运行时校验。|接口返回缺少字段时如何处理？
联合类型如何进行可靠收窄？|用字面量判别字段、typeof 或自定义类型守卫区分分支。为每个分支定义可用字段，让非法组合在类型层面更难表达。|仅判断对象存在并不能证明全部字段合法。|新增一种状态怎样让遗漏分支报错？
泛型相比直接写联合类型有什么价值？|泛型表达输入与输出之间的关联，而联合类型往往只列举可能值。为必要的能力增加约束，保留调用者的具体类型信息。|无意义的泛型会增加阅读负担。|如何约束参数必须具有 id？
never 怎样帮助穷尽检查？|分支全部处理后剩余类型应为 never。将默认分支传给接收 never 的函数，可以在新增联合成员时暴露未处理路径。|不要用强制断言掩盖未覆盖分支。|接口新增错误码怎样驱动编译失败？
interface 与 type 应如何选择？|二者都可描述对象；type 便于联合、映射等组合，interface 支持声明合并和扩展。团队应围绕公开契约和可维护性统一约定。|两者没有适用于所有项目的性能优劣结论。|库作者为什么要注意声明合并？
为什么只写类型无法保障接口数据安全？|类型检查在编译阶段发挥作用，网络响应仍需运行时检查。对缺失字段、错误枚举、版本兼容和失败响应建立显式处理。|将 JSON 断言为接口只是在告诉编译器相信你。|如何避免类型定义与校验规则漂移？
如何设计支持多种状态的请求结果类型？|用 success、error、loading 等判别状态绑定各自字段，使成功数据和失败信息不会无条件同时存在。让消费方必须处理明确分支。|大量可选字段会制造本不该存在的组合。|缓存旧数据与刷新中的状态怎么表达？
## Web 平台工程师|http|先明确浏览器约束和协议语义，再给出验证步骤与失败边界。
强缓存和协商缓存有什么区别？|新鲜缓存可以直接复用；需要验证时向服务端发送条件请求，由验证结果决定复用缓存或返回新内容。策略需考虑敏感内容与版本更新。|304 仍涉及请求，不能当成完全没有网络成本。|带 hash 的静态资源如何更新？
CORS 预检为什么会出现？|跨源请求不满足简单请求条件时，浏览器可能先发送 OPTIONS 检查服务端允许的方法和请求头。服务端要正确返回匹配策略。|CORS 是浏览器访问控制，不是服务端身份认证。|携带凭证时通配来源有什么问题？
Cookie 与 localStorage 如何选择？|先看传输、生命周期和访问范围。Cookie 可配 HttpOnly 等属性并自动附带于适用请求，localStorage 由脚本访问；二者都不能单独解决全部安全风险。|不要把一种存储方式描述成绝对安全。|如何考虑 CSRF 与 XSS 两类威胁？
Flex 和 Grid 布局各适合什么场景？|Flex 适合主要沿一条轴分配空间，Grid 适合同时安排二维轨道。根据内容尺寸、重排和响应式目标选择，而不是按流行程度决定。|固定像素堆砌不能替代布局约束。|卡片标题长度不同时如何对齐底部？
语义化 HTML 对交互有什么帮助？|原生按钮、表单和地标提供语义及默认键盘行为。先选正确元素，再补充必要 ARIA，减少用 div 重造控件的负担。|添加 role 不能自动获得键盘行为。|自定义弹窗如何管理焦点？
WebSocket 和 SSE 怎么选择？|双向交互可考虑 WebSocket，服务端向浏览器单向流式推送可考虑 SSE。还要设计重连、鉴权、消息去重与代理超时。|长连接不代表消息一定只到达一次。|断线后如何恢复遗漏消息？
如何避免 DOM 操作引入 XSS？|把不可信内容作为文本写入，确需 HTML 时采用适合上下文的净化策略，并结合 CSP 等纵深措施。检查 URL、属性和富文本不同入口。|仅替换尖括号无法覆盖全部注入上下文。|允许用户输入链接时需要校验什么？
## 前端性能工程师|perf|先采集真实用户与实验室证据，定位瓶颈，再验证改动收益和回归。
首屏慢应该怎样拆解问题？|区分网络等待、关键资源、主线程执行与渲染阶段，结合瀑布图和性能轨迹定位。优先优化实际瓶颈，再用相同设备和负载对比。|不要把打包体积当成首屏体验的唯一原因。|缓存命中和未命中应如何分别测？
长任务影响交互时如何处理？|定位连续占用主线程的工作，拆分批次或移到合适的 Worker。让输入尽快获得反馈，同时避免拆分造成过多协调开销。|异步函数内部的重计算仍可能阻塞主线程。|任务间如何让出执行机会？
图片优化需要考虑哪些维度？|按显示尺寸提供合适分辨率与格式，合理使用响应式图片和加载优先级，并预留尺寸减少布局跳动。首屏关键图不要盲目懒加载。|压缩率更高不代表所有设备解码都更合适。|弱网下先展示什么内容？
前端代码分割的边界怎么确定？|围绕路由、功能访问概率和共享依赖切分，观察请求瀑布与重复下载。避免拆得过细造成串行等待和大量小请求。|分包数量增加不必然加快加载。|公共依赖变化如何影响长期缓存？
不定高虚拟列表的难点是什么？|可视范围依赖累计高度，先估算后测量并修正偏移；上方项目尺寸变化时补偿滚动锚点，保持阅读位置稳定。|只减少 DOM 数量会忽略测量和焦点问题。|跳转到远处项目时如何定位？
如何建立前端错误监控闭环？|采集错误、版本、设备与关联上下文，做好去重与敏感信息处理。将告警关联到影响范围，修复后用同版本趋势验证下降。|只统计报错次数难以判断受影响用户数。|source map 如何兼顾排障和访问控制？
如何判断性能优化确实有效？|明确指标与用户分层，比较相同条件下的分布和尾部表现。将实验结果与真实用户数据交叉验证，检查功能和资源消耗回归。|单次跑分提高不代表所有用户体验提升。|低端设备与高端设备结果相反怎么办？
